# 从航空飞行记录器借鉴什么：抗毁、无裁量、权威解译

>  companion to [ARCHITECTURE.md](ARCHITECTURE.md) · 本文件只讲可公开核实的技术事实与设计借鉴，
>  不涉及任何实施进度或内部决策。

---

## 引言

智能体黑匣子借用了"飞行记录器"这个名字，就应该认真问一句：
**真实的航空黑匣子，究竟靠什么让它的记录可信？**
期待看到密码学方案的人可能会意外——它主要不是靠密码学，而是靠三件事：
**物理抗毁、写入端无裁量、事后由有资质的机构解译。**

---

## 1. 真实机制（多源公开资料，2026 年核实）

### 1.1 写入端无裁量

飞行记录器通电即自动启动，数据实时采集自传感器与飞机系统；
机组**只能查阅，不能控制记录器工作或改动记录内容**。
民航要求保留断电前至少 25 小时飞行数据与 2 小时音频，记录不可更改、不可删除。

这一条与本项目第一性原理完全同构：**可信记录的前提是写入端没有裁量权**。
信任对象是"规则有没有被绕过"，不是"记录者是否可信"。

### 1.2  crash-survivable memory unit（CSMU）

固态记录芯片装在一个专门设计的抗毁单元里，典型为三层防护：

-  innermost：铝合金内壳，直接包裹存储板；
- 中间：干硅石等隔热材料（约 1 英寸），抵御事故后火烧；
- 外层：不锈钢或钛合金铸壳（约 0.25 英寸），承受冲击与穿刺。

公开标准中的严苛测试包括：约 3400g 冲击（6.5ms）、500lb 钢针从 10 英尺穿刺、
5000psi 静态挤压 5 分钟、1100℃ 火焰 1 小时、6000 米水深压力与盐水浸泡 30 天、
航空燃油/液压油等液体腐蚀。

记录器通常装在飞机尾部——事故统计中该部位存活率最高。
外壳涂成醒目的国际橙并贴反光条；配水下定位信标（37.5kHz 声脉冲，30 天，
后续标准要求提升至 90 天）与陆上应急定位发射机。

### 1.3 它是一台设备，不是一个裸盘

飞行数据记录器内部有处理器与固化固件；部分实现运行实时操作系统（RTOS）。
前端常配飞行数据获取单元（FDAU），负责传感器到记录器之间的数据采集与管理。
CSMU 只是整机里的"抗毁存储单元"，不是整台记录器。

**通用操作系统缺席是设计选择**：通用 OS 的可安装软件、可修改配置恰恰是攻击面。
功能固化、写入端无裁量，才保证"通电自动记录、不受操作人员控制"。

### 1.4 不追求实时云同步

把全部飞行数据实时上传到云端，理论上可行，实践中障碍包括：
全球覆盖不足与卫星带宽成本、数据量大、传输过程中被篡改或泄露的风险、
以及独立供电必须支撑到最后时刻（落水后信标还要工作数十天）。

**"关键记录不依赖主机在线"与"只锚摘要不发明细"** 是本项目从这条得到的直接印证。
航空的答案是"把证据稳固地留在本机介质、事后由权威机构取回解译"——
这与"外部锚定只锚哈希、不把明细暴露在链路上"是同一个方向。

### 1.5 读取端有资质门槛

记录芯片的数据以专用编码存储，需专业设备与人员解译；
重大事故通常由国家级航空管理部门或具备资质的国际机构分析。
**能拿到介质 ≠ 能解读、更 ≠ 能裁定**——这是"验证权可与实现方分离"的现实先例。

## 2. 能借鉴什么、不能借鉴什么

| 航空机制 | 可借鉴性 | 说明 |
|---|---|---|
| 写入端无裁量 | **强** | 与本项目的机械 append 同构，是可信记录的真正来源 |
| CSMU 多层抗毁 + 装尾部 | **强** | 对应"抗物理灭失强于主机存储"的工程要求 |
| 不做实时云同步 | **强** | 印证"不依赖主机在线、只锚摘要不发明细" |
| 读取端资质门槛 | **强** | 对应"外部可独立复算"，但不可宣称等同于适航资质 |
| 橙色外壳 / 定位信标 | 中 | 对应"可恢复性"——设备丢了能找回，不必照搬声学信标 |
| 循环覆盖、容量够用就好 | 中 | 启发定义"最小必要记录窗口" |
| 密码学防篡改 | **不可借** | 航空记录器几乎不做密码学防篡改；相关加密方案属学术提议，非适航强制 |
| 固定安装 + 事故后整体回收 | **不可直接借** | 这是"事后物理取回"，不等于运行时的热插拔模型 |

**校位**：说航空黑匣子证明密码学防篡改有效是错误的。
它证明的是"物理抗毁 + 无裁量写入 + 权威解译"足以撑起可信的事故证据。

本项目相对航空的增量，是把"言行差额"做成**可被外部独立复算的判定单元**——
这是工程思路上的推进，不是对航空方案的替代，也不意味着已达成了同等可信度。

## 3. 对介质策略的具体启示

1. **可拔插优先，本地次之**：主机损毁、被查扣或整盘接管时，可拔插介质可提前转移——
   这是航空"整体回收"思路的现实等价物。本地存储承担连续性与索引兜底，不作为权威正本。
2. **抗毁不能只靠"能拔下来"**：可拔插介质本身通常不如主机盘耐冲击，
   需借鉴 CSMU 的壳/隔热/存放位置思路，否则"可拔插"只是方便拔，不等于抗毁。
3. **按证据强度分层投入**：弱证据端不必上最强防护；强证据端才配硬件级闸门。
4. **离线窗口必须标记**：介质拔离期间记录中断，须在账本中显式留痕，
   与"掉线检测标记日志段缺失"是同一纪律。
